# 个人空间与卡通低模阶段交付

日期 2026-09-09。范围依据 [v1.1 PRD](FocusSpace_产品需求文档_PRD_v1.1.md)。原有计时、Presence、结算、管理与公开加入服务保留；本阶段未更改统计公式。

## 体验入口

当前体验版本：`http://localhost:3001/space`，沿用原服务端口，未登录会先进入登录页面。首页「进入个人空间」和顶部「个人空间」均可进入。新账号注册后进入 `/space?setup=1`，可保存或跳过。默认头像和上传入口位于顶部昵称的个人资料弹窗。

启动现有服务：`npm run setup` → `npm run build` → `npm start`，遵守 `.env` 的部署配置。也可在停止原服务后运行 `npm run start:local`，使用仅本机的 3002 端口。同一数据库只运行一个服务进程。远程部署需同步最新前后端产物并执行迁移。

## 持久化与协议

User 新增 characterConfig、onboarding、avatarImage、avatarVersion；头像以有界的规范 PNG 存在 SQLite BLOB 中，数据库备份同时覆盖头像。PersonalSpace 以 userId 为主键/外键，一账号一个空间，存 config、revision、updatedAt。角色配置属于 User；空间配置独立于 Room 与 StudySession。

Room 新增 nullable spaceSnapshot、spaceOwnerId。创建事务从登录用户的 PersonalSpace 读取，保存 config、seed、ownerId、ownerName、sourceRevision。客户端无法指定来源账号。spaceOwnerId 记录资产归属；已有 ownerId 是可转交的主持人。个人保存绝不写入已有房间快照。旧房间 spaceSnapshot 为 null，按原 theme 加默认基础家具渲染。

| 接口 | 权限与行为 |
| --- | --- |
| GET /api/users/me/space | 已登录本人，返回完整可编辑配置、版本和稳定种子 |
| PUT /api/users/me/space | 严格 schema，校验 revision；事务保存角色和空间；冲突 409；广播当前房间角色变化 |
| POST /api/users/me/avatar | 本人，原始 PNG/JPEG/WebP 请求体；2 MB 限制，真实解码后生成 256×256 PNG |
| GET /api/avatars/:id | 已登录后读取规范 PNG；原始文件从不对外提供 |
| PATCH /api/users/me | 原昵称/默认头像，加 removeAvatar；拒绝未知字段与外部图片地址 |
| POST /api/rooms | 沿用原入口，严格拒绝客户端 spaceOwnerId、spaceId 等来源字段 |
| GET /api/rooms/:id/snapshot | 沿用成员鉴权；返回空间快照及每个成员的公开角色、头像 URL |

配置编辑接口仅本人可读写。房间广播仅包含展示所需的角色和创建时空间快照，不下发其他成员当前个人空间编辑配置。账号角色不包含空间编辑权限。主持转交、下架、结束继续经过原服务端验证。新快照房间的 room:theme 命令返回 SPACE_FROZEN；旧房间继续支持原 LOBBY 主题规则。

头像由 sharp 以 limitInputPixels=16000000 解码。格式必须与允许的 MIME 对应，拒绝多帧；旋转、裁切、缩放后重编码，剥离原始元数据。Express 限制 2 MB 并返回明确的 413。客户端也检查大小/类型和图像解码，仅作为提前反馈，服务端校验不可省略。

## 稳定资产与程序化美术

`packages/shared/src/personal.ts` 是资产目录与校验来源。ASSETS / ASSET_CATALOG 含稳定 ID、类别、免费标志、适用房型、槽位、预览颜色及生成参数。配置只持有轻量 ID、version=1；没有任意 URL、任意坐标或无限数组。新增兑换系统可直接引用这些 ID，当前开放目录中的资产全部免费。

| 类别 | 稳定 ID 前缀 | 可选数 | 生成位置/范围 |
| --- | --- | --- | --- |
| 肤色/发型/发色 | skin. / hair. | 3 / 3 / 3 | 统一头部比例 |
| 服装/配饰 | outfit. / accessory. | 4 / 4 | 躯干、头部固定装配 |
| 房型 | room. | 2 | 矩形窗书屋、拱窗小筑 |
| 桌子/椅子 | desk. / chair. | 各 2 | 长桌及八个固定座位 |
| 桌面/墙面/窗边/地毯 | desktop. / wall. / window. / rug. | 各 2 | 预设兼容槽位，不占学习座位 |
| 灯光 | light. | 2 | 天光、暖灯；三种主题调色 |

RoomArt 创建房间/家具，AvatarModel 创建可组合角色，geometryKit 复用几何与材质并统一释放。StudyRoomScene 负责灯光、镜头、场景更新和 HTML 状态标签；CharacterScene 使用相同角色模型预览。桌面高度约 1.18 米，椅垫约 0.64 米，身体从 0.73 米起；双段手臂与书页配合，姿态指数插值过渡。稳定种子由用户 ID 哈希产生，房间种子在创建时冻结；无 Math.random 外观参数。

3D 动态按 30 FPS 限速、像素比最高 1.5；离屏/后台停止绘制，尊重减少动态偏好。阴影使用单个方向光，移动端保留卡片降级、计时、任务和聊天。角色/空间改动仅替换必要资源，场景/头像资源卸载时释放；不为头像改变重建整个房间。

## 增量迁移

迁移目录：`prisma/migrations/202609090001_personal_space/`。仅 ALTER ADD COLUMN、CREATE TABLE 和为现有 User 插入默认空间，不清空、不重建学习记录。老用户 onboarding=SKIPPED，避免升级阻塞学习；新用户默认 PENDING。旧房间快照保持 null，不重新写入原历史布置。

升级顺序：先 `npm run db:backup`，停止占用 Prisma 引擎的旧服务，执行 `prisma generate` 和 `npm run db:deploy`，再使用新生产构建启动。迁移后的数据库不能直接给旧版 Prisma 客户端使用；回滚应同时恢复迁移前数据库备份与旧产物。

本工作区已实际执行迁移。迁移前一致性备份：`backups/focusspace-2026-09-09T13-14-02.148Z.db`。只读校验确认备份中八张业务表的原字段、原记录均保留，备份后至旧服务停止之间新增的业务记录也保留；不把用户期间的新活动当作迁移清理。当前服务已在原 3001 端口启动，健康接口正常。

## 剩余限制

基础房型共用八座长桌布局，差异在窗型与风格；不支持自由移动、拖拽和装修碰撞。动作是轻量关节组，不提供骨骼编辑。手机上座号和符号简写，完整状态在成员列表查看。旧历史没有追溯性的空间快照。保存遇到另一标签页冲突时保留草稿，需主动载入服务端版本；未实现自动合并。头像存库适合当前单实例规模，后续大规模运营需独立对象存储。Three.js 动态分包约 511 KB，构建有大于 500 KB 的提示；未引入外部纹理/人物模型。成长、兑换、永久空间访客仍属于后续阶段。
