# 第六阶段：公共共学与管理员系统

本阶段沿用账号和 Cookie 会话、房间成员与座位、串行 SQLite 写队列、阶段时间轴、有效在线区间、幂等结算、恢复及 24 小时消息保留。新增公开入口、统一房主转移与管理员后台，不重建学习数据。

## 角色与体验入口

- 普通用户：注册 /register，登录 /login，首页 / 查看公开房间、创建房间及个人记录。
- 房主：/rooms/:roomId 的“房主管理”可切换公开/私有、主动转交，或转交后自己离开；“结束共学”明确确认结束所有人的共学。
- 管理员：初始化后登录，右上角“管理后台”进入 /admin。后台含管理概览、用户管理、房间与 Session、有限期消息、操作审计。
- 非管理员直接打开 /admin 返回 403；未登录页面访问转至登录。所有 /api/admin HTTP 操作重新校验服务器角色；实时房主操作重新校验当前身份。

## 初始化与本地交付

1. 执行 npm run db:backup 保留一致性备份，然后停止本项目旧服务。
2. 执行 npx prisma generate、npm run db:deploy、npm run build。本阶段只使用 202609080003_public_admin 增量迁移。
3. 执行 npm run start:local，默认地址 http://127.0.0.1:3002。可用 LOCAL_PORT 指定其他本地端口。此入口强制回环监听和本地 Origin，沿用 .env 的 DATABASE_URL，不启用隧道或修改公网配置。
4. 在 /register 创建自己的账号与密码，然后在项目目录执行 npm run admin:init -- 你的账号 --confirm。该命令只提升指定的已有正常账号，不创建密码、不打印密码，不解封账号。建议维护时停止服务后运行；已有管理员重复运行无变更。
5. 重新登录并进入 /admin。初始化和角色提升与 LOCAL_OPERATOR 审计在同一数据库事务内。后续可用相同命令添加备用管理员。首期没有角色编辑接口或复杂权限平台。

严禁 migrate reset、删除旧库或任意修改 StudyRecord。最后一个未封禁管理员不可封禁；服务端串行事务避免两名管理员同时封禁导致零个可用管理员。

## 公开房间规则

新建默认私有；旧房间迁移后全部保持私有。首页公开列表每页 12 条，按创建时间及 ID 倒序，可按主题和阶段筛选，显示主题、占用人数（包含宽限期保留座位）、容量、阶段、专注/休息节奏、下一轮预计开始时间。大厅显示等待房主开始；Focus 预计为当前阶段结束加休息时长；Break 为本阶段结束。

列表只输出白名单字段，不输出房间码、成员身份、任务、后台字段。公开加入使用房间 ID，服务端在串行事务内再次检查公开属性、结束状态、容量及一人一个活跃房间，登录状态和封禁状态也再次检查。列表可能在点击前变化，此时返回房间已满、已结束、已转私有等明确错误，页面可刷新重试。邀请房间码继续沿用旧加入规则。

中途加入立即同步当前阶段，从入座连接后开始个人计时，不等待下一轮、不补记过去的时间。公开列表为按需刷新的快照。

房主可自行转私有，原成员继续；管理员下架同时设置本场下架标记，禁止房主或新房主重新公开，房间码邀请不受影响。强制结束调用统一 finishSession，结算当前及曾参与成员；重复结束不会重复结算。

## 房主接任规则

主动转交的目标必须是本房有效成员、在线、非 AFK、未封禁。只改变 ownerId 与 revision；Session、阶段边界、Ready、任务、座位、学习统计均保留。主动转交后旧房主立即成为普通成员。

断线宽限期以最后一个有效连接断开计算，默认 60 秒。多标签中仍有有效连接时不启动接任。宽限期结束、主动离开或封禁房主时使用统一逻辑：

1. 过滤在线、非 AFK、未封禁、尚未离开的其他成员。
2. 按本次 joinedAt 升序，其次 seatIndex 升序，最后 userId 字典序选择一人。
3. 有合适成员则转交；无合适成员才结束全房。断线结束时间沿用持久化宽限截止时间。

超时和主动离开释放原座位；原房主超时后须通过公开入口或邀请码重新入座，按当前普通成员身份恢复自己的任务，不自动夺回权限。宽限期内重新连接则正常恢复。主动转交且未离开的人刷新/重连仍按最新身份恢复。服务重启后不将旧连接误当成在线候选。

所有操作共用串行写队列和事务。每次超时重新读取当前 ownerId，旧房主断线事件不能结束已交给新房主的房间。转交后自己离开的请求也支持相同 requestId 重试确认。

## 后台使用与隐私

概览从数据库与当前 Socket 集合读取真实数据：连接数为实时连接总数，在线用户按 userId 去重，活跃房间是存在有效实时订阅且未结束的房间。另列进行中 Session（包括无人在线的宽限期房间）、已结束 Session、公开房间、用户和封禁用户、24 小时内未移除消息。统计为最近刷新时的快照。

用户按账号/昵称搜索、每页 20 条；封禁必须说明至少两个字原因。提交前服务器生成影响预览，说明登录会话数、房间和成员影响。确认时比较影响指纹，状态变化则要求重新预览。封禁事务撤销所有旧会话、处理成员资格和房主接任，提交后关闭该账号所有实时连接；旧 Cookie 与重新登录均不能绕过。解封必须重新登录，旧令牌与旧座位不恢复。

房间页面查看状态、Session、节奏和当前成员。不能修改历史学习记录。管理员即使知道房间 ID，也不能读取非本人参与房间的学习快照；管理 DTO 不查询任务标题，不因 ADMIN 角色获得私人任务读取权。

有限期消息管理仅显示最近 24 小时内容，可按房间 ID 筛选。移除将数据库原文置空，同时清除 chat:send 回执原文，重试返回 MESSAGE_REMOVED。向当前房间广播新快照，客户端用服务器完整窗口替换消息状态；旧 revision 消息不能覆盖移除结果。后续查询仅显示“消息已移除”。断线客户端清空聊天展示并于恢复后重新读取。已过期消息按既有保留任务清理，不因管理系统延长保留时间。

每个有效敏感操作先预览、填原因再确认。成功变更和 SUCCESS 审计同事务提交；事务失败回滚业务变更，另记 FAILED 和错误码。审计保存操作者 ID、对象 ID、原因、时间、结果、必要的影响摘要和请求 ID，不复制消息原文、私人任务、密码或令牌。请勿在人工填写的原因中粘贴敏感正文。数据库彻底不可写时无法承诺写入失败审计，但不会提交未审计的成功变更。相同成功请求重试返回原审计编号。

## 演示路线

1. 准备三个普通账号，另将一个自己的账号初始化为管理员，分别使用独立浏览器上下文登录。
2. A 创建公开房间，B 在首页筛选主题后加入。C 以管理员查看概览，A 开第二个房间标签，观察连接数增加而在线用户与活跃房间数不变。
3. A/B 准备，A 开始；可在 DEMO_MODE=true 时通过房间原有按钮切换 45/15 秒演示节奏。B 中途加入时无需等待下一轮。
4. A 给 B 转交，观察房主标识和操作权实时交换，当前倒计时、任务和座位不重置。用“转交后自己离开”展示与“结束共学”的不同影响。
5. 本地短时验证可设置 DISCONNECT_GRACE_MS=2500。关闭房主的所有标签，观察符合规则成员接任；原房主重新加入不恢复房主身份。
6. 管理员下架：列表刷新后不再出现，原成员继续。休息期发送消息，再在后台说明原因移除，房间客户端立即隐藏原文。
7. 管理员封禁房主：全部标签退出登录，旧 Cookie 无法重连，符合条件成员接任。解封后重新登录。
8. 管理员强制结束，所有参与者查看同一场结算；后台审计显示原因和成功摘要，重复请求不重复计算。

## 验证与限制

npm run test:admin 使用独立临时数据库、实际旧迁移、2.5 秒宽限期、真实 HTTP/Socket 与生产浏览器。覆盖迁移保留、HTTP/页面/实时越权、提权输入、最后管理员、去重指标、公开容量竞态及状态变化、转交/超时/封禁接任、移除回执与 DOM、失败审计事务回滚和结算幂等。隔离数据库直接设短阶段边界，不增加生产环境的任意改历史接口。

维持单进程 SQLite、每房 8 人、每房一次 Session；不新增多实例、复杂 RBAC、举报申诉或复杂社区。没有后台修改/重算历史的入口。公开目录与后台列表需刷新获取最新快照，已连接房间通过实时广播更新。审计长期保留，尚无独立归档策略。未实测 Safari/iOS 与实体低端设备；公网发布不在本阶段交付范围。
