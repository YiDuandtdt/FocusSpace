# 第二阶段交付：多人共学核心闭环

本阶段基于 PRD 与开发设计文档增量实现。复用一期 npm workspaces、Cookie 鉴权、房间资格、SQLite 写队列、CommandReceipt、按用户过滤的快照、多标签页和恢复逻辑。

## 启动与升级

在项目根目录停止旧开发服务后执行 `npm run setup`、`npm run dev`，访问 http://localhost:5173。首次安装先 `npm ci`。生产运行使用 `npm run build`、`npm start`，访问 http://localhost:3001。

迁移 `202609070002_sessions` 只新增 PhaseInterval、PresenceInterval、Task、ChatMessage、StudyRecord 及外键和索引；保留所有一期数据。Windows 的 Prisma 引擎被旧服务占用时，停止本项目服务后重试 setup。不要执行 migrate reset 或删除数据库。

演示时在 `.env` 设置 `DEMO_MODE=true` 并重启，在房间节奏面板选择 45/15 秒预设。普通模式的分钟范围不变，演示预设只能在服务端开关打开后使用。

## 实现行为

- Session：房主和所有保留成员均须在线、Ready 且非 AFK。开始事务建立第 1 轮 FOCUS；服务端每秒检查到期会话，并在命令前补齐过期阶段，以旧截止时间为下一阶段起点。BREAK 后自动递增轮次，客户端不能提交阶段和时间。现有全局队列适配单 SQLite 写入者。
- 客户端：服务端快照控制 Lobby/Focus/Break/Ended，倒计时组件以请求往返时间校准 `performance.now()`。到零只确认一次快照；刷新、重连、切回前台和定期同步恢复权威阶段，断线禁止写入。
- 任务：Session 内私人任务增删改、完成和取消完成；标题 1–200 字，最多 100 项。更新和删除检查任务所属用户、Session 与 version，跨标签冲突提示重读。使用明确 completed 值，重试使用同一 requestId。公共查询只投影 userId/completed，其他成员和管理员都不能通过快照取得任务标题。
- 聊天：仅当前有效成员在 BREAK 发言；每条 1–500 字、每用户每 2 秒一条。数据库消息时间用于限频，多标签页与重启不能绕过；CommandReceipt 与消息同事务保存。消息按纯文本渲染，以固定消息 ID 去重；FOCUS 收起并禁用输入。确认超时保留草稿，不自动补发。
- 结束：主动结束、房主离开和断线超时共用 finishSession。在单个事务中关闭阶段/个人区间、保存 StudyRecord、写入 ENDED 和递增版本，再广播。唯一 `(sessionId,userId)` 约束和已结束检查防重复记录，不同 requestId 的重复结束也返回已有结果。
- 结果：房间内展示个人有效秒数、完整 Focus 轮次、任务数量/比例和共学人数；独立 `/sessions/:sessionId/summary` 页面刷新读取保存结果。HTTP `GET /api/sessions/:id/summary` 只返回该参与者自己的记录；外部账号不能查看，已离开的原参与者可在结束后读取。

## 统计与恢复

有效专注 = 在线非 AFK 区间和 FOCUS 区间交集的毫秒数之和，最后向下取整为秒。重叠区间合并；完整轮次要求连续覆盖整个正常结束的 Focus，碰巧同一毫秒的暂离/断线区间仍视为中断。主动结束的部分 Focus 计时长但不计完整轮次。

共同学习人数 = 与本人有正时长 Focus 交集的其他用户去重数量，排除自己、仅大厅相遇或只在休息重叠的人。任务计数取结束时未删除的最终任务，零任务比例为 null。

同账号多个标签页只有一个有效个人区间；最后连接断开或 AFK 关闭区间，回来再开启。普通断开以检测时刻截止，心跳超时以最后有效心跳截止。服务重启先用已保存 lastSeenAt 关闭未完成的个人区间，再恢复阶段时间轴并给予房主重连宽限，停机不补计个人学习时间。

## 验证与演示

运行 `npm run typecheck`、`npm run build`、`npm run test:flow`、`npm run test:session`。测试服务和数据库均在 `.tmp` 隔离创建，失败保存日志和截图，不修改日常数据。

本次上述四项检查均通过。第二阶段还验证了进行中的迟到/离开重返/断线恢复、房主断线超时的一次结算、默认关闭演示预设，以及桌面和 390px 移动端无横向溢出的完整浏览器流程。专注、休息和结果截图保存在测试输出目录，已进行视觉检查。

本机现有库已成功应用新增迁移；迁移前后 User=2、Room=3、RoomMember=5、StudySession=3，原有实体数量一致，原开发服务恢复后 `/api/health` 返回正常。

两个独立浏览器登录不同账号 → 创建/加入房间 → 设置演示节奏 → 分别写任务并准备 → 房主开始 → 勾选任务看对方进度（看不到标题）→ 刷新/暂离/回来 → 等待 BREAK 发送消息 → 自动进入第 2 轮 → 房主结束 → 两端查看各自结果 → 打开结果页刷新确认持久化。

## 具体限制

单实例、最多 8 人；不做房主转移。无 3D、BGM 和复杂视觉效果。无任务公开设置、聊天历史查询/断线消息补发、个人历史列表和房间总体共同专注时长。聊天室只展示本次连接收到的最近 100 条消息；已保存消息仍在数据库，但没有查询入口。网络往返校时是近似值，阶段以服务器为准。
