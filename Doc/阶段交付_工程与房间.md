## 业务与恢复规则

创建房间原子建立 Room、LOBBY StudySession 和房主成员。6 位房间码使用不易混淆的大写字母和数字，冲突检查后重新生成。一个用户只能处于一个未结束房间，单房容量为 8；断线宽限期内仍占用座位。

先通过 HTTP 获得成员资格，再通过 `room:join` 订阅。读取 URL 和 Socket 订阅不授予新资格，非成员读取统一返回 ROOM_NOT_FOUND。服务端广播只含昵称、Avatar、座位和状态，不含账号凭据。

HTTP 创建/加入以及 Socket 写命令把 CommandReceipt 与业务结果保存在同一事务。相同 requestId 和内容复用结果，内容改变返回 CONFLICT。每次持久化状态变化递增 revision，提交后广播按访问者构造的快照。SQLite 单进程串行写队列也防止同一用户并发加入不同房间。

服务端按 userId 聚合同房连接，一个账号多标签页只占一座。最后一个房间连接关闭才标记 DISCONNECTED；刷新可在 60 秒内恢复原座位和 Ready/AFK。普通成员超时释放座位，重返复用成员记录；房主主动离开或断线超时结束房间。主动离开对同账号所有房间标签页生效。

服务重启把活动成员标记为离线并重新给予宽限期，原会话、节奏、成员记录、座位和幂等凭据保留。Socket.IO 内置 ping 检测失联，15 秒持久化活跃成员 lastSeenAt；客户端每 30 秒及切回前台时同步快照。当前每次周期对齐发送完整快照，容量限定为 8 人；后续可在有实际需要时优化为 revision 轻量对齐。

房间页面断线禁用操作；命令确认超时先取快照，再以同 requestId 重试一次。离开导致资格失效时仍可重试已保存的离开凭据。没有继续使用未确认的乐观状态。

登录使用 bcrypt、随机不透明 Cookie 令牌及数据库摘要；校验会话过期与撤销。HTTP 写入校验 Origin；Socket 握手校验 Origin，同源轮询 GET 缺少该头时使用 Sec-Fetch-Site 与 Referer 联合校验。注册登录、HTTP 写入和 Socket 命令有基本频率限制。

## 验证结果

- 类型检查和生产构建通过；生产服务提供同源网页/API/Socket，支持房间深链接刷新。
- 隔离数据库关键链路通过：账号与 Cookie、来源限制、创建/加入幂等、非成员隔离、容量与并发跨房间限制、准备/AFK/节奏/资料同步、多标签页、离开后权限、重复离开、重返、退出撤销、进程重启和房主超时。
- 两个独立浏览器上下文通过：注册 → 登录 → 创建/加入 → Ready 广播 → 刷新保持状态 → 离开与重新加入 → 房主结束 → 退出后保护页面跳转登录。
- 已检查桌面和 390px 移动端截图；浏览器未出现未捕获脚本错误，移动端无横向溢出。

验证脚本使用自己的临时数据库与端口，结束后停止测试进程。用户体验入口与命令见根目录 README。
